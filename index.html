Fantasy Console 16-Bit

Built from scratch by koiafk in a single HTML file. Features a custom assembler, 16-bit CPU, and memory-mapped VRAM.

Memory: 65,536 Bytes. VRAM: 0x8000-0x8FFF. Stack: 0xFF00-0xFFFF. Keyboard MMIO: 0xFF00.

================================================ koiafk OS v1.0 // guide.md "now with 100% more nostalgia" ================================================ 1. WHAT IS THIS? A complete fantasy console in one HTML file: a tiny CPU with an 8-bit data path and 16-bit addresses, a 2-pass assembler, 64KB of RAM and a 64x64 screen. You type assembly, it turns into machine code, the CPU runs it, pixels appear. That is the whole magic trick. 2. 30-SECOND QUICK START 1. File -> Load Demo -> Checkerboard 2. Press Run and watch the screen fill in. 3. Type a clock speed in Hz (1 to 1,000,000) or pick a preset. 1 MHz is the speed of a real 6502. 4. When the program hits HLT the status bar turns green and says "Success". 5. Press Run again. It restarts from address 0000. 3. THE CPU A accumulator, 8-bit. STA can only store A. X index register, 8-bit. Added to the address in STA. Y spare register, 8-bit. Great as a loop counter. PC program counter, 16-bit. SP stack pointer, 16-bit. Starts at FFFF, grows down. ZF zero flag. 1 when the last result was zero. ADD, SUB, INC, CMP, TAX, TXA, TAY and TYA update ZF. LDA and LDX do not. 4. WRITING CODE ; this is a comment loop: ; a label (letters, digits, _) LDA #5 ; '#' = this exact number, 0 to 255 STA 0x8000,X ; store A at address + X JZ done ; jump to a label if ZF = 1 Numbers can be decimal (32768), hex (0x8000) or $8000. The assembler is strict. If something is wrong it prints a red error in the console, wipes the program from memory, and the CPU refuses to run until you fix it. Things it will yell about: - an unknown opcode - an immediate without '#', or one bigger than 255 - STA without ",X" - INC without a register (INC X or INC Y) - a label that does not exist, or one defined twice 5. THE "A GETS CLOBBERED" TRAP TXA and TYA overwrite A, and STA always stores A. So if you TXA inside a loop and then STA, you are storing X, not your pixel colour. Reload A (LDA #1) at the top of the loop. Every demo does this on purpose. 6. MEMORY MAP 0000-7FFF code and general RAM 8000-8FFF video RAM, 64x64 pixels, one byte each. 0 = off, anything else = on. pixel address = 8000 + row*64 + column FF00 keyboard port (WASD or arrow keys) FF00-FFFF stack, grows downward from FFFF Only writes between 8000 and 8FFF touch the screen. 7. DEMOS (File -> Load Demo) Full Screen Fill lights all 4096 pixels Diagonal Stripes diagonal lines, period 4 Checkerboard classic 1x1 checker Border Frame a one-pixel frame around the screen Clear Screen switches every pixel off Assemble keeps whatever is on the screen, so you can run Fill, then load Clear Screen and watch it wipe. Reset clears everything, screen included. 8. DEBUGGING Step runs one instruction Gutter click a line number to toggle a breakpoint Pause freezes the CPU, Run resumes The yellow bar in the editor shows the line about to run. 9. FAQ Q: Why does Run restart after HLT? A: HLT is the end of the movie. Press Run to watch it again. Q: Can my program read the keyboard? A: The port at FF00 is wired up, but there is no instruction that loads from memory yet. For now it is decoration. Q: Why does the window not close? A: Click the X and find out.
